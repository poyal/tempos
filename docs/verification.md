# 검증 기록

## 외부 API 목업 기준 적용 · 2026-10-13

사용자 기준에 따라 일반 E2E는 외부 날씨·Google Calendar·OAuth·위치를 모두 목업으로 검사한다. Win32 창·JSON 파서·캐시·DPAPI 저장·재시작은 실제 경로를 사용하고, `--windows-real`에서는 CPU·GPU·메모리·디스크·네트워크 수집만 실제로 유지한다. 기준은 [E2E 안내](e2e.md)와 루트 [AGENTS.md](../AGENTS.md)에 고정했다.

TestHost는 로컬 실측 옵션에서도 목업 HTTP를 유지하며 WinHTTP 세션을 만들지 않는다. OAuth 브라우저 승인은 앱 소유 루프백 콜백으로 대체해 실제 콜백 검증·토큰 교환·갱신·목록/이벤트 파서를 통과한다. 미등록 요청은 거부하고 E2E 종료 시 목업 요청 기록을 확인한다. 기본 E2E에 배포 `Tempos.exe`를 지정하면 실행 전에 거부하는 검사도 통과했다. 실제 API 검사는 별도 사용자 요청과 `--integration-live-api`로 분리한다.

| 검사 | 통과 | 실패 | SKIP |
| --- | ---: | ---: | ---: |
| 핵심 검사 | 202 | 0 | 0 |
| `--api-mock` | 58 | 0 | 0 |
| `--weather` | 63 | 0 | 0 |
| `--windows-real` — 실제 로컬 수집 + 목업 API/위치 | 40 | 0 | 1 |
| E2E 합계 | **161** | **0** | **1** |

OAuth 승인 거부·교환·갱신·만료, 캘린더 페이지 합치기·빈 목록·401/403/429/503·시간 초과·비정상 응답·캐시 유지·연결 해제를 확인했다. 위치는 부산 목업 좌표의 선택·적용·재시작을 통과했으며 OS 위치 API를 호출하지 않았다. SKIP 1개는 OS 마우스 입력의 커서 이동을 관측하지 못한 항목이다. 실제 API 가용성과 실제 위치 권한은 일반 E2E 완료 조건에 포함하지 않는다.

최초 목업 E2E는 데이터 수집 완료 직후 아직 갱신 주기가 오지 않은 접근성 문구를 읽어 실패했다. 수집 완료 후 선택 위젯을 적용하는 UI 동작을 명시하고 실제 일정 문구를 확인했다. 최종 실행은 같은 TestHost 바이너리에서 수행했으며, 초기 실패·이전 실행·최종 실행·API 요청 기록·해시를 [목업 검사 JSON](validation/2026-10-13-api-mock.json)에 구분해 남겼다. 이전 실행의 성공 수와 의도한 배포 앱 실행 거부를 위 통과 수에 중복 합산하지 않는다. 이번에는 실제 외부 API를 호출하지 않았다.

## 실제 Windows 배포 E2E · 2026-10-13

Windows 11 Pro 10.0.26300 x64의 실제 사용자 세션에서 ZIP을 새로 풀어 `Tempos.exe`로 검사했다. TestHost·예제 공급자를 사용하지 않았다. CPU·GPU·메모리 실측, 전체 네트워크, Windows가 보고한 전체 로컬 드라이브, 실제 Open-Meteo 응답, 두 모니터의 DPI, 위젯 설정·저장·재시작을 확인했다. [실제 화면과 실행별 결과](validation/windows-2026-10-13/README.md), [각 단언·실행 파일 해시·최초 실패 JSON](validation/windows-2026-10-13/results.json)을 보존한다.

실제 캡처에서 **메모리 수집 이력이 누적되지 않아 그래프가 비어 있는 결함**을 발견했다. 이력 누적 대상에 메모리를 포함하고 실제 수집기 회귀 검사와 그래프 선 픽셀 검사를 추가했다. 수정 전 회귀 검사는 실패했고 수정 후 핵심 검사 **195개**가 통과했다. 확정된 날씨 디자인은 변경하지 않았다.

| 실행 파일 | 결과 | 범위 |
| --- | --- | --- |
| 수정 전 `4db9504c…` | E2E **856개 통과·실패 0개·SKIP 3개** | 11개 모드의 최종 실행. 메모리 그래프 결함은 캡처 검토에서 별도 발견 |
| 수정 후 `0a7b400e…` | E2E **143개 통과·실패 0개·SKIP 2개**, 핵심 **195개 통과** | 새 ZIP의 실제 공급자·메모리 그래프·초기 실행·공유 수집·표시 옵션·재시작 |

두 바이너리의 성공 수를 합산하거나 수정 후 11개 모드를 모두 다시 실행했다고 표시하지 않는다. 첫 옵션 검사는 실제 낮은 트래픽의 `B/s`를 허용하지 않아 실패했고, 수신·송신의 전체 바이트 단위 범위를 검사하도록 보완한 뒤 다시 통과했다. 초기 실패도 보고서에 남겼다.

OS `SendInput`의 커서 이동과 `Shell.ToggleDesktop`의 효과가 관측되지 않아 실제 OS 드래그·Win+D는 SKIP이다. 실제 현재 위치 조회는 좌표의 Open-Meteo 전송에 대한 명시적 동의가 없어 자동 승인 검토에서 거부되었으며, 이번 실행에서는 위치 API를 호출하지 않았다. 기본 지역의 실제 날씨 응답과 구분한다. 실제 계정 인증·로그온·모니터 분리·동시 다중 NIC 트래픽·장기 누수 검사는 이번 범위가 아니다.

## 최종 디자인·앱 대조 · 2026-10-13

확정된 날씨를 유지하고 나머지 8종에 같은 제목·아이콘 기준점, 20 DIP 윤곽선 아이콘, 24 DIP 모서리와 글자 위계를 적용했다. 시계는 전 크기에서 디지털만 표시한다. 메모리는 CPU/GPU와 같은 그래프 구성이며, 시스템 정보는 선택한 사양 목록 A의 정보 순서를 따른다. 디스크 S/Slim/M은 선택 볼륨, L은 전체 로컬 볼륨을 표시한다. 6개를 넘으면 12초마다 다음 목록으로 넘어가며 읽을 수 없는 볼륨도 목록에서 숨기지 않는다.

[최종 디자인 폴더](../design/final-2026-10-12/index.html)에 15개 기준 보드를 정리했다. 날씨 2장과 공통 팔레트 원본은 SHA-256까지 일치한다. 초기 생성 이미지에서 발견한 위치·아이콘 불일치는 나머지 시안을 공통 HTML/CSS/SVG 구성 요소로 다시 제작하여 해결했다. 이 독립 기준과 [실제 앱 120개 캡처](../design/final-2026-10-12/app-review.html)를 비교했다. 위젯 9종 37개 크기, 시계 16개 조합, 디스크 0/1/3/6/8개와 자동 순환, 테마 9개, 긴 이름·오류·일정 초과·설정 화면을 육안 검수했다. 값·날짜 차이와 픽셀 단위 차이는 허용하며 공통 배치와 정보 구성을 기준으로 삼았다.

E2E·패키지 합계 **1,304개**, 핵심 검사를 합하면 **1,497개 자동 확인 통과**다. 최종 실행에는 실패·SKIP이 없다. 서로 다른 기능 개수나 전체 코드 커버리지를 뜻하지 않는다. 위 수치는 모두 동일한 최종 Release/TestHost 바이너리에서 실행했고, 실행별 시각·각 확인 항목·실행 파일 해시를 [최종 검증 JSON](validation/2026-10-13-final-design.json)에 보존한다. 이전 날짜의 통과 수를 합산하지 않는다.

디자인 제작 도구는 12개 보드의 텍스트 경계와 공통 제목 위치를 확인했다. 검수 페이지는 로컬 브라우저에서 13개 확인을 통과했다. 15개 보드 및 실제 캡처 로딩, 데스크톱·모바일 너비, 메모 복원, 검수 JSON 내보내기를 포함한다. README에는 시안 대신 실제 앱의 전체 예시·디스크·날씨·캘린더·선택별 설정을 넣었으며 [촬영 조건](screenshots.md)을 별도로 기록했다.

### 초기 실패와 캡처 보완

- 표시 옵션 검사의 첫 실행은 항상 위 해제 후 위젯이 앞에 열린 Explorer보다 위에 있을 것으로 기대하여 실패했다. `WS_EX_TOPMOST` 해제와 바탕화면 부모 복구, 창의 생존·표시·재시작 보존을 확인하도록 고쳤다. 실제 바탕화면 히트 테스트와 동일한 검사라고 설명하지 않는다.
- 시계 검사의 첫 캡처는 항상 위 옵션을 저장하기 전에 탭을 바꿔 배경용 창에 가려졌다. UI 단언만 통과한 초기 이미지는 채택하지 않았다. 옵션 저장 순서를 고치고 실제 내용 픽셀 검사를 추가한 후 16개를 다시 촬영·검수했다.
- 설정창 캡처의 일부는 위젯에 가려졌고 투명한 창 테두리에 바탕화면이 섞였다. 촬영할 때만 설정창을 올려 49개 내부 지점이 해당 창에 속하는지 검사하고 클라이언트 영역만 캡처했다. UI·디자인 E2E를 다시 실행하여 공개 이미지를 교체했다.
- 검수 페이지 내보내기 검사의 초기 도구는 이전 14개 보드의 파일을 읽었다. 실행마다 브라우저 프로필·다운로드 폴더를 분리하여 최종 15개 보드와 입력 메모를 확인했다.

이전 실패·미채택 캡처의 경로와 보완 내용은 최종 검증 JSON에 남겼으며 성공 수에 중복 합산하지 않는다. 개인 프로파일과 전체 바탕화면 캡처는 공개 자료에 포함하지 않았다.

실제 Windows 위치 권한 승인·측위는 모의 좌표 검사와 구분하며 이번에 직접 실행하지 않았다. 물리 마우스 입력·Win+D, 실제 다중 NIC 동시 트래픽, 모니터 분리, 실제 Google OAuth·기상청 키 인수 검사, 모든 크기×테마×배율 조합도 이번 완료 범위가 아니다. 이번 디자인 변경 이후 새 30분 성능·24시간 누수 검사를 수행하지 않았으므로 아래 과거 성능 수치를 새 바이너리의 측정값으로 사용하지 않는다.

## 날씨 공급자 변경 검증 · 2026-10-12

기상청/Open-Meteo 전역 선택, 프로파일 복원과 자동 시작 처리를 구현하고 README를 사용자 매뉴얼로 정리했다. [이번 실행 원본 요약](validation/2026-10-12-weather.json)에 명령·시각·각 확인 항목·실행 파일과 빌드 소스 SHA-256을 기록했다. 아래의 2026-10-09 이전 수치는 과거 기록이며 이번 바이너리의 재검사 결과로 합산하지 않는다.

데스크톱 E2E 합계는 **982개 확인 통과, 1개 SKIP, 실패 0개**다. Windows 로그인 옵션은 격리된 레지스트리에서 등록·해제·체크 복원·실패 복구를 확인하고, 공백·한글이 있는 데이터 경로를 포함한 등록 명령으로 앱을 다시 실행했다. 실제 Windows 로그아웃·로그인은 하지 않았으므로 SKIP으로 남겼다.

날씨 E2E는 정상 종료와 강제 프로세스 종료 후 설정 복원, 공급자와 키 보존, 구버전 기본값, 레이아웃 내보내기·가져오기, 저장 실패, 같은 위치 요청 공유, 오류·한도·비정상 응답, 늦은 이전 공급자 응답, WMO 상태와 크기별 출처를 확인했다. 제어된 HTTP 응답도 실제 파서를 통과시켰다. 기상청 개인 키와 Google OAuth 실연결은 이번에 검사하지 않았다.

문서용 연동 화면 2장과 S/Slim/M/L 4장을 직접 열어 글자·출처·배치를 검토했다. [촬영 조건](screenshots.md)과 원본 실행을 연결했으며 개인 인증키·일정을 사용하지 않았다. 안개·뇌우·알 수 없는 상태 화면도 검토했다. 실제 Open-Meteo 연결은 별도 네이티브 요청 결과로 구분한다.

배포 실행 파일로 기존 2개 위젯 레이아웃을 열고 9종 추가·정렬·저장·재시작을 검증했다. 같은 Release 실행 파일을 재빌드 없이 ZIP으로 포장하여 해시 일치, 지역 3,837개, 실제 공급자 사용, TestHost 제외와 정상 종료를 확인했다. 문서·검증 요약의 후속 패키징은 바이너리를 바꾸지 않는다. 최종 ZIP 해시는 `artifacts/package.json`과 인접 `.sha256`에 보관한다. 공개 릴리즈는 게시하지 않았다.

## 실측에 따른 설계 조정

기본 렌더링은 **공유 Direct2D DC 렌더 타깃 + 창별 32비트 DIB + UpdateLayeredWindow**다. 글꼴과 브러시를 공유하고 변경 시에만 그린다. DirectComposition 구현도 코드에 남아 있으나 기본 경로는 아니다. 브라우저, GPU 프레임 루프, 강제 Working Set 축소를 사용하지 않는다.

초기 1분 비교에서 DirectComposition 경로의 최대 Private Bytes 약 65.4 MiB, Working Set 약 61.6 MiB가 저주기 DC 경로에서는 약 18.2 / 39.6 MiB였다. 이 수치는 짧은 기술 비교 결과이며 최종 성능 인수 결과로 사용하지 않는다.

Windows 11 빌드 26300와 Wallpaper Engine 환경에서 wallpaper WorkerW 또는 Progman의 직속 자식은 실제 화면에 가려졌다. **SHELLDLL_DefView 안의 아이콘 목록 위**에 위젯 창을 연결하는 경로로 수정했고 실제 위치 검사와 레이어를 포함한 화면 캡처로 표시를 확인했다. Explorer 내부 창 계층에 의존하므로 다른 Windows 업데이트·바탕화면 확장 도구에도 동일하게 동작한다고 보장하지 않는다. 실제 바탕화면 아이콘 위치를 자동 이동시키지는 않는다.

하나의 바탕화면 부모 아래에서는 Windows가 자식에게 같은 창 DPI를 줄 수 있다. 위젯의 렌더링·좌표·히트 테스트는 대상 모니터의 DPI를 별도로 사용하여 서로 다른 모니터 배율을 맞춘다.

GPU PDH 인스턴스의 LUID가 대문자 16진수로 반환되어 DXGI 키와 일치하지 않던 오류를 수정했다. 대소문자를 정규화하고 프로세스별 값을 같은 엔진으로 모으며, 합계 카운터를 중복 계산하지 않는다. 실제 NVIDIA GeForce RTX 4070 Ti에서 UIA 요약에 사용량이 표시되는 것을 확인했다.

반복 생성·제거 시험에서 기존 힙의 5초 후 Private Bytes 증가가 2,793,472바이트로 기준을 넘었다. Windows 11의 [Segment Heap](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests#heaptype)을 매니페스트로 선택한 뒤 동일한 짧은 시험에서는 1,081,344바이트로 줄었다. 이 비교만으로 누수 원인을 단정하지 않는다. 최종 반복 시험은 별도로 5분 준비·1,000회 생성/제거·5분 안정화 조건을 사용한다. Working Set 강제 비우기나 테스트 직전 힙 정리 호출은 사용하지 않는다.

### 재현하고 수정한 문제

- **임시 배치된 위젯이 추가 과정에서 숨겨짐:** 연결되지 않은 모니터 ID를 가진 큰 위젯을 현재 화면에 임시 배치한 뒤 두 개를 더 추가하면, 수정 전 실행 파일에서 기존 위젯 일부의 `placed/visible`이 false로 바뀌었다. 추가 위치 계산이 저장된 원래 모니터만 확인하여 실제 점유 공간을 놓쳤다. 이제 현재 계산된 배치의 점유 영역을 사용한다. 같은 회귀 검사는 수정 후 공간 부족을 알리고 모든 기존 위젯을 유지했으며, 원래 모니터 ID는 재연결을 위해 보존했다. 실제 케이블 분리 시험은 아니다. 사용자가 겪은 상황과 원인이 동일하다고 단정하지 않는다.
- **저장 실패를 성공으로 표시:** 설정 파일을 읽기 공유만 허용한 채 열어 교체를 차단하면, 기존 코드는 저장 실패 후 성공 메시지로 덮어쓰고 메모리 설정을 변경했다. 변경 후보를 먼저 저장하고 성공해야만 반영하도록 바꿨다. 적용·추가·삭제·숨김·전체 테마·표시 옵션·가져오기에서 오류 표시, 디스크/실행 상태 보존, 종료 후 재시작을 검사했다. 달 이동과 드래그도 같은 저장 순서를 사용한다. 교체 실패 시 임시 파일도 지운다.
- **항상 위 해제 누락:** 체크를 해제해도 네이티브 창의 topmost 상태가 남았다. 바탕화면으로 돌아가기 전에 `HWND_NOTOPMOST`로 해제하고 부모 변경 시 기존 표시 스타일을 보존한다. [SetWindowPos 동작](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)을 따랐다.
- **가져온 전체 테마와 설정창 선택 불일치:** 가져온 테마로 설정창 선택도 동기화한다.
- **작은 12시간제 시계의 텍스트 겹침:** S 크기의 오전/오후를 별도 줄에 배치하고 Slim의 글자 크기를 조정했다. 4개 크기 × 12/24시간 × 초 표시 유무, 총 16개 조합의 실제 위젯 영역을 캡처했다. S와 Slim의 12시간 표시를 직접 확인했다.
- **표시 옵션과 접근성 요약 단위 불일치:** 화씨, 네트워크 바이트 단위, 디스크 이진 단위를 UIA 요약에도 반영하고 결과 문자열을 검사한다.
- **잘못된 일정 날짜 허용:** 종일 날짜 뒤의 불필요한 문자열, 0년, 잘못된 날짜 및 숫자가 아닌 시간대 오프셋을 거부한다. 기존 연동 모의 응답 검사와 함께 핵심 테스트에 포함했다.

### 확대된 기능 검사

`tests/e2e/Regression.cs`에 별도 실행 모드를 추가했다. 새 회귀 검사는 UIA와 소유한 네이티브 컨트롤/창의 메시지를 사용한다. 물리 입력 검증과 구분한다.

- `--persistence`: 9종의 개별 추가·적용, 정렬 모드 반복, 설정창 실제 닫기, 재시작, 숨김 상태 재시작, 중간 위젯 삭제, 화면/셸 알림 후 저장 ID·네이티브 창 개수·표시 여부·화면 히트 테스트를 대조한다. AddressSanitizer 앱에서도 같은 흐름을 실행했다.
- `--placement`: 임시 모니터 배치와 공간 부족 시 기존 위젯 보존을 검사한다. 수정 전 실패 자료도 유지한다.
- `--failures`: 파일 잠금, 잘못된 투명도·시간대·가져오기, 중복 ID·65개 위젯·지원하지 않는 버전, 손상 원본 보관과 정상 백업 복구를 검사한다.
- `--capacity`: 같은 종류 64개의 고유 ID와 창, 65번째 추가 거부, 전체 삭제, 빈 레이아웃 재시작을 검사한다.
- `--options`, `--clock-layout`: 위젯 간 옵션 격리, 100/150/200% 실제 창 크기, 초 갱신, 표시 단위, 항상 위 해제, 전체 테마와 개별 테마, 월 이동, 시계 표시 조합을 검사한다.
- `--saved-layout`: 작업 폴더에 남은 기존 4개 위젯의 설정을 복사하여 실제 `Tempos.exe`로 열고, 9종을 추가한 13개 위젯의 저장·정렬 종료·재시작·화면 표시를 확인했다. 날씨 지역 적용은 패키지 지역표의 정밀 좌표로 정규화되므로 이를 예상 결과에 반영하며, 원본 파일은 수정하지 않는다.

추가 핵심 검사는 Release와 AddressSanitizer에서 각각 **98개** 통과했다. 기존 크기 행렬·동작·드래그 메시지·시각·실제 CPU/GPU/메모리 수집 검사도 다시 실행했다. 셸의 바탕화면 보기/물리 Win+D는 여전히 환경 제약으로 SKIP이다. 실제 인증키/OAuth, 실제 모니터 분리, Explorer 종료, 절전·잠금, 24시간 누수 검증은 여전히 완료로 표시하지 않는다.

검사 도구 보완 과정의 실패도 원본 실행 폴더에 남겼다. 숨겨진 설정 컨트롤의 UIA 탐색은 네이티브 핸들 검사로 바꾸고, 파일 대화상자 종료 뒤 앱의 저장 처리가 끝날 때까지 기다린다. 제한된 실행 컨텍스트에서 실패한 화면 캡처와 DPAPI 검사는 실제 사용자 세션에서 다시 실행했다. 실패 실행과 성공 실행의 확인 수를 합산하지 않는다.

### 디자인 기준에 따른 전체 검수

[디자인 가이드](design-guide.md)를 먼저 세우고 계획의 DIP 규격·크기별 필수 정보, 생성된 Concept 01 시안, 실제 실행 화면을 비교했다. [79개 캡처의 비교 결과와 남은 차이](validation/design-2026-10-08/README.md)에 37개 크기별 구성, 9개 공통 팔레트, 설정 4개 탭, 날씨·장치·캘린더의 29개 상태를 정리했다. 모든 자동 검사를 육안 디자인 합격으로 취급하지 않았다.

누락된 CPU/GPU Slim·M 그래프와 L 최대값, M 시계의 아날로그와 L 정보 위계, 메모리·디스크의 크기별 용량 정보, 네트워크 M 그래프·방향 범례를 보완했다. 긴 모델·일정 제목은 말줄임하고 큰 시스템 카드에서는 줄바꿈을 허용한다. 날씨 L은 다음 4시간의 기온·아이콘·강수 확률을 표시하며, 시간별 아이콘은 도시의 일출/일몰을 반영한다. 비·눈이 오는 밤도 낮과 구분한다. 캘린더는 연결 전 안내와 일정 없음 상태를 구분한다.

작은 흰 글자를 위해 공통 팔레트의 명도를 조정하고 불투명 카드의 두 끝점에 대해 대비 4.5:1을 검사한다. 이는 임의 배경화면·투명도·고대비 모드를 포함하는 전체 접근성 인증이 아니다. 사용자 투명도는 그대로 보존한다. 제작용 시각 데이터 명령은 `TEMPOS_TEST_HOST` 빌드에만 있으며 배포 파일에서는 사용할 수 없다.

최종 핵심 검사는 팔레트 확인 9개를 더해 Release·AddressSanitizer에서 각각 **107개** 통과했다. 예외 검사 도우미 안에서 대비 검사가 반복 집계되는 테스트 배치 오류도 수정했고, 중복된 170개 집계는 최종 수치에 사용하지 않는다.

### 반복 자원 검사와 테스트 보완

최종 파일의 첫 반복 검사(`e2e-20261009-000926`)는 Private Bytes -712,704바이트, GDI/USER 증가 0이었지만 핸들 +2개로 **실패**했다. 이 실패는 삭제하거나 성공 수에 합산하지 않는다. 검사 코드를 검토하며 다른 프로세스의 편집 컨트롤에 `SetWindowText`를 호출한 뒤 투명도의 실제 저장값을 대조하지 않던 허점도 발견했다. `WM_SETTEXT`로 입력하고 매 회차 투명도·배율·테마의 저장값을 검사하도록 수정했다. 이전 반복 결과를 투명도 변경의 증거로 사용하지 않는다.

수정한 반복 검사는 준비 100회·300초 대기, 본 검사 1,000회·300초 안정화 조건에서 통과했다. Private Bytes +1,138,688바이트(**1.09MiB**), 핸들 **-2개**, GDI/USER **0개**다. 저장값 검사는 준비를 포함한 1,100회 모두 통과했고, 마지막에 원래 5개 위젯의 ID·창·실제 바탕화면 표시와 정상 종료도 확인했다. 2MiB 및 핸들 증가 0의 기준은 완화하지 않았다.

`stress-handles.json`은 반복 중 100회, 대기 중 30초 간격으로 핸들 종류와 메모리·스레드 수를 기록한다. 이번 추적에서는 기준 369개에서 이벤트 1개·스레드 핸들 1개가 늘어 371개가 됐다가 안정화 120초에 367개로 감소했다. 추가된 스레드의 시작 주소는 기존 작업 스레드와 같은 `ntdll.dll` 진입점이었으며 해당 핸들이 해제된 것도 확인했다. 시스템의 작업 스레드 유지와 일치하는 관찰이지만, 종류별 기록이 없던 첫 실패의 원인을 소급해 확정하지는 않는다. [Windows 스레드 풀 설명](https://learn.microsoft.com/en-us/windows/win32/procthread/thread-pools)과 [핸들 스냅샷 구조](https://github.com/winsiderss/phnt/blob/master/ntpsapi.h)를 참고했다. 원시 실패 수치와 최종 추적 요약을 검증 JSON에 함께 보존한다.

성능 검사 첫 시작 시 새 소유 창 탐색 코드가 PowerShell의 `null` 문자열을 빈 창 제목으로 전달해 설정창을 찾지 못했다. 표본 수집 전 실패이며 성능 불합격 수치로 해석하지 않는다. 제목 포인터를 `IntPtr.Zero`로 전달하도록 수정한 뒤 프로세스 ID·위젯 종류·배치·표시 검사를 통과한 측정만 최종 결과로 사용한다. 이 준비 단계 실패도 JSON에 별도 기록했다.

측정 구간의 Private Bytes 변화는 5종 +991,232바이트, 9종 +1,769,472바이트다. 두 측정 모두 핸들·GDI·USER 변화는 각각 0이다. 최대값과 구간 변화량을 구분하며 메모리 누수 없음으로 확대 해석하지 않는다. 짧은 측정에서 나타난 5종·9종 CPU 평균의 차이를 위젯 수 증가에 따른 성능 개선으로 해석하지 않는다.

이 측정은 최종 파일의 **3분 회귀 측정**이며 `standardDuration: false`다. 30분 인수 시험 또는 24시간 장기 실행을 완료했다는 의미가 아니다. 실제 날씨 키와 Google 계정은 없으며, 앱 프로세스 CPU·Private Bytes·Working Set에는 DWM이나 전체 GPU 메모리가 포함되지 않는다. 예산 상한, 표본 수, 실제 경과 시간과 각 판정은 [최종 실행 기록](validation/2026-10-09-audit.json)에 보존한다.

## 위젯 구성·설정 개선 검증 (2026-10-12)

선택한 위젯에 해당하는 설정만 표시하고 빈 자리를 줄여 재배치했다. 표시 옵션 탭도 선택한 종류의 항목만 보여준다. 날씨는 정적인 배경 장면과 현재 위치 한 번 찾기를 추가했으며, 위치 결과는 지역을 선택한 뒤 적용 버튼으로 저장한다. 재실행하거나 시간이 지나도 자동 추적하지 않는다. 전체 네트워크는 연결된 물리 인터페이스를 합산하고 필터·터널을 제외하여 중복 집계를 피한다.

메모리는 CPU/GPU의 사용률·최근 60초 그래프·평균/최대 구성을 공유한다. 위젯의 출처 문구와 클릭·더블클릭·우클릭 동작을 제거하고 읽기 전용 접근성을 유지했다. 정렬 모드의 이동은 유지했다. 모든 카드 크기에 24 DIP 모서리를 적용했다.
