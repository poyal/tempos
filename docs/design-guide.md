## 검수 범위와 차이 기록

자동화 통과와 사람이 화면을 읽고 판단한 결과를 따로 기록한다. 캡처만 생성하고 검수 완료로 취급하지 않는다. 각 구성의 실제 화면, 9개 테마, 날씨 상태, 설정 4개 탭, 빈 화면·오류·투명도·배치를 확인한다. 모든 크기×배율×테마×상태의 곱 전체를 육안 확인했다고 주장하지 않는다.

시안의 설정 패널은 방향 참고다. 현재 설정은 Win32 네이티브 탭·콤보·입력란을 사용한다. 실시간 미리보기/취소, 슬라이더, 오른쪽 배치 편집 패널 등 구현되지 않은 시안 요소는 검수 결과에서 차이로 공개한다. 이를 구현된 기능으로 바꿔 적거나 임의의 합격으로 덮지 않는다.

최종 증거·발견 사항·수정·미검증 조건은 [검증 기록](verification.md)과 `docs/validation/`의 실행 기록에 남긴다.

## 날씨 공급자 선택 추가 · 2026-10-12

기상청과 Open-Meteo 선택은 연동 탭에서 확인하며, 위젯·접근성 요약에 출처 문구를 붙이지 않는다. 갱신 지연 문구는 별도로 표시한다. WMO 안개·뇌우·미확인 코드를 구분하고 낮밤·시간별 예보에도 공통 상태를 사용한다. 자동 배경에는 정적인 구름층·강수·별·안개를 사용하며 고정 테마·고대비·유효하지 않은 날씨에는 장면을 그리지 않는다. 연동 탭은 전역 적용 범위, 키 입력 활성 여부와 비상업적 이용 조건을 설명한다.

## 구성 재검토 · 2026-10-12

[시계 3안·시스템 정보 2안·디스크 2안](../design/review-2026-10-12/index.html)은 크기별 구성 비교용 이미지다. 시계·시스템·디스크의 구성 변경은 이 시안 단계이며, 디스크 L의 전체 드라이브 표시는 제안이다. 이미지의 예시 수치와 픽셀 비율은 구현 규격을 대신하지 않는다. 현재 구현에는 공통 모서리·날씨 배경·출처 제거·클릭 제거·메모리 그래프·선택별 설정·위치 한 번 찾기·전체 네트워크를 반영한다.

## 최종 구성 검수본 · 2026-10-12

사용자가 선택한 최종 디자인 검수본은 [final-2026-10-12](../design/final-2026-10-12/index.html)에 모았다. 원본 `galaxy-v1`과 이전 비교 시안은 보존한다. 10월 13일 공통 구성으로 다시 정리하고 앱에도 반영했다. 위의 10월 12일 구성 재검토 절은 당시 제안 단계의 기록이다.

- 날씨: 기본 크기별 시안과 상태별 배경을 원본 그대로 유지한다.
- 시계: 모든 크기에서 아날로그를 제거하고 디지털 시간·날짜·요일 중심으로 구성한다.
- 디스크: `galaxy-v1/08-disk.png`의 S·Slim·M을 유지하고 L만 드라이브 목록 A안으로 합친다. L의 전체 드라이브 표시는 3개 샘플에 한정하지 않는다.
- 시스템 정보: 사용자가 고른 사양 목록 A안의 정보 구성을 유지하고 제목·아이콘을 공통 기준점에 맞춘다.
- 메모리: RAM 윤곽선 아이콘과 CPU/GPU 공통 사용률·60초 그래프·평균/최대 구성을 사용한다.
- 공통: 비교 시안은 같은 블루 테마로 통일한다. 실제 앱에서는 9개 테마를 종류와 무관하게 선택한다. 공통 제목 줄·20 DIP 아이콘·24 DIP 모서리, 조회 전용 동작, 선택별 설정을 적용한다.

구성 선택·출발 이미지·규격은 `manifest.json`에 기록한다. 초기 이미지 생성 결과의 배치 불일치는 `boards.html`/`components.js` 공통 구성으로 교체했다. `node scripts/render-design.cjs`로 PNG를 재생성하며, 아이콘 좌표와 콘텐츠 경계를 검사한다. `prompts.json`은 교체 전 초기 생성 기록이다. 날씨 2장과 테마 원본은 SHA-256으로 동일성을 확인한다.

디스크 L은 읽을 수 없는 볼륨도 목록에 남긴다. 4~6개는 조밀한 행, 7개 이상은 6개씩 12초마다 자동 순환한다. 사용자가 선택한 개별 볼륨은 S/Slim/M으로 돌아가면 다시 적용된다. 접근성 요약은 현재 페이지와 관계없이 모든 볼륨을 포함한다.

디자인 시안과 실제 앱 캡처는 [앱 대조 페이지](../design/final-2026-10-12/app-review.html)에서 구분해 확인한다. 샘플 데이터는 실제 PC의 수치와 달라도 되지만 제목·아이콘·본문 위계와 모서리 기준은 같아야 한다. 사용자 검수 메모는 브라우저에 저장하고 JSON으로 내보낼 수 있다.
