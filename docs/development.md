## 실측에 따른 설계 조정

기본 렌더링은 **공유 Direct2D DC 렌더 타깃 + 창별 32비트 DIB + UpdateLayeredWindow**다. 글꼴과 브러시를 공유하고 변경 시에만 그린다. DirectComposition 구현도 코드에 남아 있으나 기본 경로는 아니다. 브라우저, GPU 프레임 루프, 강제 Working Set 축소를 사용하지 않는다.

초기 1분 비교에서 DirectComposition 경로의 최대 Private Bytes 약 65.4 MiB, Working Set 약 61.6 MiB가 저주기 DC 경로에서는 약 18.2 / 39.6 MiB였다. 이 수치는 짧은 기술 비교 결과이며 최종 성능 인수 결과로 사용하지 않는다.

Windows 11 빌드 26300와 Wallpaper Engine 환경에서 wallpaper WorkerW 또는 Progman의 직속 자식은 실제 화면에 가려졌다. **SHELLDLL_DefView 안의 아이콘 목록 위**에 위젯 창을 연결하는 경로로 수정했고 실제 위치 검사와 레이어를 포함한 화면 캡처로 표시를 확인했다. Explorer 내부 창 계층에 의존하므로 다른 Windows 업데이트·바탕화면 확장 도구에도 동일하게 동작한다고 보장하지 않는다. 실제 바탕화면 아이콘 위치를 자동 이동시키지는 않는다.

하나의 바탕화면 부모 아래에서는 Windows가 자식에게 같은 창 DPI를 줄 수 있다. 위젯의 렌더링·좌표·히트 테스트는 대상 모니터의 DPI를 별도로 사용하여 서로 다른 모니터 배율을 맞춘다.

GPU PDH 인스턴스의 LUID가 대문자 16진수로 반환되어 DXGI 키와 일치하지 않던 오류를 수정했다. 대소문자를 정규화하고 프로세스별 값을 같은 엔진으로 모으며, 합계 카운터를 중복 계산하지 않는다. 실제 NVIDIA GeForce RTX 4070 Ti에서 UIA 요약에 사용량이 표시되는 것을 확인했다.

반복 생성·제거 시험에서 기존 힙의 5초 후 Private Bytes 증가가 2,793,472바이트로 기준을 넘었다. Windows 11의 [Segment Heap](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests#heaptype)을 매니페스트로 선택한 뒤 동일한 짧은 시험에서는 1,081,344바이트로 줄었다. 이 비교만으로 누수 원인을 단정하지 않는다. 최종 반복 시험은 별도로 5분 준비·1,000회 생성/제거·5분 안정화 조건을 사용한다. Working Set 강제 비우기나 테스트 직전 힙 정리 호출은 사용하지 않는다.

앱과 TestHost가 같은 지역표를 동시에 복사하던 빌드 경쟁도 공유 `tempos_data` 대상으로 제거했다. 매니페스트 변경은 명시적 링크 의존성으로 추적한다. UI 캡처는 투명 레이어를 포함하는 `CAPTUREBLT`를 사용하며, 각 E2E 실행 폴더에 분리 저장한다.

### 재현하고 수정한 문제

- **임시 배치된 위젯이 추가 과정에서 숨겨짐:** 연결되지 않은 모니터 ID를 가진 큰 위젯을 현재 화면에 임시 배치한 뒤 두 개를 더 추가하면, 수정 전 실행 파일에서 기존 위젯 일부의 `placed/visible`이 false로 바뀌었다. 추가 위치 계산이 저장된 원래 모니터만 확인하여 실제 점유 공간을 놓쳤다. 이제 현재 계산된 배치의 점유 영역을 사용한다. 같은 회귀 검사는 수정 후 공간 부족을 알리고 모든 기존 위젯을 유지했으며, 원래 모니터 ID는 재연결을 위해 보존했다. 실제 케이블 분리 시험은 아니다. 사용자가 겪은 상황과 원인이 동일하다고 단정하지 않는다.
- **저장 실패를 성공으로 표시:** 설정 파일을 읽기 공유만 허용한 채 열어 교체를 차단하면, 기존 코드는 저장 실패 후 성공 메시지로 덮어쓰고 메모리 설정을 변경했다. 변경 후보를 먼저 저장하고 성공해야만 반영하도록 바꿨다. 적용·추가·삭제·숨김·전체 테마·표시 옵션·가져오기에서 오류 표시, 디스크/실행 상태 보존, 종료 후 재시작을 검사했다. 달 이동과 드래그도 같은 저장 순서를 사용한다. 교체 실패 시 임시 파일도 지운다.
- **항상 위 해제 누락:** 체크를 해제해도 네이티브 창의 topmost 상태가 남았다. 바탕화면으로 돌아가기 전에 `HWND_NOTOPMOST`로 해제하고 부모 변경 시 기존 표시 스타일을 보존한다. [SetWindowPos 동작](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)을 따랐다.
- **가져온 전체 테마와 설정창 선택 불일치:** 가져온 테마로 설정창 선택도 동기화한다.
- **작은 12시간제 시계의 텍스트 겹침:** S 크기의 오전/오후를 별도 줄에 배치하고 Slim의 글자 크기를 조정했다. 4개 크기 × 12/24시간 × 초 표시 유무, 총 16개 조합의 실제 위젯 영역을 캡처했다. S와 Slim의 12시간 표시를 직접 확인했다.
- **표시 옵션과 접근성 요약 단위 불일치:** 화씨, 네트워크 바이트 단위, 디스크 이진 단위를 UIA 요약에도 반영하고 결과 문자열을 검사한다.
- **잘못된 일정 날짜 허용:** 종일 날짜 뒤의 불필요한 문자열, 0년, 잘못된 날짜 및 숫자가 아닌 시간대 오프셋을 거부한다. 기존 연동 모의 응답 검사와 함께 핵심 테스트에 포함했다.

### 확대된 기능 검사

`tests/e2e/Regression.cs`에 별도 실행 모드를 추가했다. 새 회귀 검사는 UIA와 소유한 네이티브 컨트롤/창의 메시지를 사용한다. 물리 입력 검증과 구분한다.

- `--persistence`: 9종의 개별 추가·적용, 정렬 모드 반복, 설정창 실제 닫기, 재시작, 숨김 상태 재시작, 중간 위젯 삭제, 화면/셸 알림 후 저장 ID·네이티브 창 개수·표시 여부·화면 히트 테스트를 대조한다. AddressSanitizer 앱에서도 같은 흐름을 실행했다.
- `--placement`: 임시 모니터 배치와 공간 부족 시 기존 위젯 보존을 검사한다. 수정 전 실패 자료도 유지한다.
- `--failures`: 파일 잠금, 잘못된 투명도·시간대·가져오기, 중복 ID·65개 위젯·지원하지 않는 버전, 손상 원본 보관과 정상 백업 복구를 검사한다.
- `--capacity`: 같은 종류 64개의 고유 ID와 창, 65번째 추가 거부, 전체 삭제, 빈 레이아웃 재시작을 검사한다.
- `--options`, `--clock-layout`: 위젯 간 옵션 격리, 100/150/200% 실제 창 크기, 초 갱신, 표시 단위, 항상 위 해제, 전체 테마와 개별 테마, 월 이동, 시계 표시 조합을 검사한다.
- `--saved-layout`: 작업 폴더에 남은 기존 4개 위젯의 설정을 복사하여 실제 `Tempos.exe`로 열고, 9종을 추가한 13개 위젯의 저장·정렬 종료·재시작·화면 표시를 확인했다. 날씨 지역 적용은 패키지 지역표의 정밀 좌표로 정규화되므로 이를 예상 결과에 반영하며, 원본 파일은 수정하지 않는다.

추가 핵심 검사는 Release와 AddressSanitizer에서 각각 **98개** 통과했다. 기존 크기 행렬·동작·드래그 메시지·시각·실제 CPU/GPU/메모리 수집 검사도 다시 실행했다. 셸의 바탕화면 보기/물리 Win+D는 여전히 환경 제약으로 SKIP이다. 실제 인증키/OAuth, 실제 모니터 분리, Explorer 종료, 절전·잠금, 24시간 누수 검증은 여전히 완료로 표시하지 않는다.

검사 도구 보완 과정의 실패도 원본 실행 폴더에 남겼다. 숨겨진 설정 컨트롤의 UIA 탐색은 네이티브 핸들 검사로 바꾸고, 파일 대화상자 종료 뒤 앱의 저장 처리가 끝날 때까지 기다린다. 제한된 실행 컨텍스트에서 실패한 화면 캡처와 DPAPI 검사는 실제 사용자 세션에서 다시 실행했다. 실패 실행과 성공 실행의 확인 수를 합산하지 않는다.

### 디자인 기준에 따른 전체 검수

[디자인 가이드](design-guide.md)를 먼저 세우고 계획의 DIP 규격·크기별 필수 정보, 생성된 Concept 01 시안, 실제 실행 화면을 비교했다. [79개 캡처의 비교 결과와 남은 차이](validation/design-2026-10-08/README.md)에 37개 크기별 구성, 9개 공통 팔레트, 설정 4개 탭, 날씨·장치·캘린더의 29개 상태를 정리했다. 모든 자동 검사를 육안 디자인 합격으로 취급하지 않았다.

누락된 CPU/GPU Slim·M 그래프와 L 최대값, M 시계의 아날로그와 L 정보 위계, 메모리·디스크의 크기별 용량 정보, 네트워크 M 그래프·방향 범례를 보완했다. 긴 모델·일정 제목은 말줄임하고 큰 시스템 카드에서는 줄바꿈을 허용한다. 날씨 L은 다음 4시간의 기온·아이콘·강수 확률을 표시하며, 시간별 아이콘은 도시의 일출/일몰을 반영한다. 비·눈이 오는 밤도 낮과 구분한다. 캘린더는 연결 전 안내와 일정 없음 상태를 구분한다.

작은 흰 글자를 위해 공통 팔레트의 명도를 조정하고 불투명 카드의 두 끝점에 대해 대비 4.5:1을 검사한다. 이는 임의 배경화면·투명도·고대비 모드를 포함하는 전체 접근성 인증이 아니다. 사용자 투명도는 그대로 보존한다. 제작용 시각 데이터 명령은 `TEMPOS_TEST_HOST` 빌드에만 있으며 배포 파일에서는 사용할 수 없다.

최종 핵심 검사는 팔레트 확인 9개를 더해 Release·AddressSanitizer에서 각각 **107개** 통과했다. 예외 검사 도우미 안에서 대비 검사가 반복 집계되는 테스트 배치 오류도 수정했고, 중복된 170개 집계는 최종 수치에 사용하지 않는다.

### 반복 자원 검사와 테스트 보완

최종 파일의 첫 반복 검사(`e2e-20261009-000926`)는 Private Bytes -712,704바이트, GDI/USER 증가 0이었지만 핸들 +2개로 **실패**했다. 이 실패는 삭제하거나 성공 수에 합산하지 않는다. 검사 코드를 검토하며 다른 프로세스의 편집 컨트롤에 `SetWindowText`를 호출한 뒤 투명도의 실제 저장값을 대조하지 않던 허점도 발견했다. `WM_SETTEXT`로 입력하고 매 회차 투명도·배율·테마의 저장값을 검사하도록 수정했다. 이전 반복 결과를 투명도 변경의 증거로 사용하지 않는다.

수정한 반복 검사는 준비 100회·300초 대기, 본 검사 1,000회·300초 안정화 조건에서 통과했다. Private Bytes +1,138,688바이트(**1.09MiB**), 핸들 **-2개**, GDI/USER **0개**다. 저장값 검사는 준비를 포함한 1,100회 모두 통과했고, 마지막에 원래 5개 위젯의 ID·창·실제 바탕화면 표시와 정상 종료도 확인했다. 2MiB 및 핸들 증가 0의 기준은 완화하지 않았다.

`stress-handles.json`은 반복 중 100회, 대기 중 30초 간격으로 핸들 종류와 메모리·스레드 수를 기록한다. 이번 추적에서는 기준 369개에서 이벤트 1개·스레드 핸들 1개가 늘어 371개가 됐다가 안정화 120초에 367개로 감소했다. 추가된 스레드의 시작 주소는 기존 작업 스레드와 같은 `ntdll.dll` 진입점이었으며 해당 핸들이 해제된 것도 확인했다. 시스템의 작업 스레드 유지와 일치하는 관찰이지만, 종류별 기록이 없던 첫 실패의 원인을 소급해 확정하지는 않는다. [Windows 스레드 풀 설명](https://learn.microsoft.com/en-us/windows/win32/procthread/thread-pools)과 [핸들 스냅샷 구조](https://github.com/winsiderss/phnt/blob/master/ntpsapi.h)를 참고했다. 원시 실패 수치와 최종 추적 요약을 검증 JSON에 함께 보존한다.

성능 검사 첫 시작 시 새 소유 창 탐색 코드가 PowerShell의 `null` 문자열을 빈 창 제목으로 전달해 설정창을 찾지 못했다. 표본 수집 전 실패이며 성능 불합격 수치로 해석하지 않는다. 제목 포인터를 `IntPtr.Zero`로 전달하도록 수정한 뒤 프로세스 ID·위젯 종류·배치·표시 검사를 통과한 측정만 최종 결과로 사용한다. 이 준비 단계 실패도 JSON에 별도 기록했다.

### 디자인 변경 후 실제 실행 파일 성능 (2026-10-09)

배포 실행 파일 SHA-256은 `4844363951828736F94618A453EB4D9088A77FFDEC6EBD4DC468B680B7E8C1A0`이다. E2E와 동시에 측정하지 않았고, 각 프로필은 별도 데이터 폴더와 프로세스를 사용한다. 숨겨진 설정창 상태에서 위젯이 모두 배치·표시된 것을 시작과 종료 시 확인한다. CPU는 논리 프로세서 16개로 정규화하며 1초 간격 표본의 실제 경과 시간으로 가중 평균한다. P95는 nearest-rank 방식이다.
