# CPU·GPU 온도

CPU/GPU 카드의 S·Slim·M·L에 사용률과 함께 섭씨 온도를 표시한다. 모델명은 M·L 카드 맨 아래의 독립된 한 줄이며 S·Slim에서는 숨긴다. 긴 모델명은 말줄임으로 표시할 수 있지만 접근성 이름에는 전체 모델명을 제공한다. 처음 설정하는 순서는 [사용자 매뉴얼의 CPU 온도 안내](../README.md#temperature)를 따른다.

## CPU 온도 켜기

앱 설정에서 **CPU 온도 표시**를 켠다. 센서 도우미가 없으면 번들 `Tempos.Sensors.Setup.exe`의 관리자 승인을 요청한다. 설치 성공과 서비스 실행이 확인된 뒤에만 설정을 켠다. 취소·실패·재부팅 필요 결과는 성공으로 저장하지 않는다. 다음 실행부터는 저장한 설정으로 자동 연결한다. 위젯 앱은 일반 권한으로 동작한다.

**센서 도우미 설치 / 복구**와 **센서 도우미 제거**도 같은 설정에서 실행한다. 제거하면 CPU 온도 표시를 끈다. 공유 PawnIO 드라이버는 다른 프로그램이 사용할 수 있으므로 남겨 둔다. 기본 앱 제거 시 센서 도우미 제거 여부를 별도로 선택할 수 있다.

GPU 온도는 별도 CPU 도우미 없이 Windows가 제공하는 선택 GPU 어댑터의 값을 사용한다. Windows/드라이버가 지원하지 않으면 `—`로 표시한다. CPU 센서는 Intel CPU Package 또는 AMD Core (Tdie), Core (Tctl/Tdie)를 선택하며 메인보드 온도나 코어 평균으로 대신하지 않는다.

온도는 `45°C`처럼 표시하며 80°C 미만은 흰색, 80°C부터 주황색, 90°C부터 빨간색이다. 이는 높은 값을 쉽게 찾기 위한 앱 표시 기준이며 기기별 최대 온도나 고장을 판단하는 기준이 아니다. CPU/GPU 사용률은 80%·95%, 메모리/디스크 사용률은 80%·90%에서 같은 순서로 색이 바뀐다. 미지원·오래된 값은 경고색을 지운다. [실제 색상 예제와 기준](validation/2026-10-17-layout-report.html#colors).

## 표시 상태

유효한 범위는 0°C 초과~150°C이며 샘플은 `max(5초, 수집 간격×2)` 이내여야 한다. 비활성·불러오는 중·미지원·도우미 연결 실패·오래된 값은 `—`로 표시한다. CPU의 상세 상태는 앱 설정에서, CPU/GPU의 상세 이유는 접근성 요약에서 확인한다. 사용률 수집은 온도 실패와 관계없이 계속한다.

CPU 위젯이 없거나 수집을 일시 중지하면 요청을 멈춘다. 절전 모드는 최소 5초 간격을 사용한다. 도우미는 마지막 요청 후 30초 이상 지나면 CPU 센서 핸들을 닫는다.

## 구현과 배포

- 앱: 네이티브 C++, 별도 작업 스레드에서 750ms 제한의 로컬 이름 있는 파이프 요청.
- 도우미: `%ProgramFiles%\Tempos\Sensors`의 .NET 10 self-contained 서비스 `TemposSensors`, 자동 시작. CPU 센서만 활성화한다.
- 프로토콜: `\\.\pipe\Tempos.Sensors.v1`, 로컬 인증 사용자만 데이터 읽기/쓰기, 원격 연결 거부. 요청은 버전·1~10초 간격만 허용한다. 명령 실행·파일 경로·드라이버 쓰기 API를 공개하지 않는다.
- 의존성: LibreHardwareMonitorLib 0.9.6, 서명·SHA-256 검증한 PawnIO 2.2.0. 버전·해시는 `third_party/sensors/dependencies.json`과 NuGet lock에 고정한다.
- 설치: 고정된 보호 폴더, 기존 서비스 경로 확인, 목록에 있는 파일만 제거. 설치 프로그램 외에는 권한 상승하지 않는다.

`scripts/build.ps1 -Preset release` 후 `scripts/build-sensors.ps1 -Download -Test`로 도우미 설치 파일을 만든다. 다운로드가 끝난 뒤에는 `-Download`를 생략한다. `scripts/package.ps1`은 도우미 설치 파일을 기본 앱 배포물에 함께 넣는다. 서비스와 드라이버를 자동으로 설치하는 빌드 단계는 없다.

## 검증 범위

`--temperature`는 설치 결과 및 센서 응답을 목업하고 실제 Windows UI·설정·재시작을 검사한다. `--windows-real`에서는 실제 로컬 Windows 센서 값을 읽되 서비스/드라이버를 설치하지 않는다. 미지원·서비스 없음은 SKIP으로 기록한다. 실제 설치·UAC·재부팅·제거 수명주기는 별도의 깨끗한 Windows 환경에서 검사해야 한다. 외부 날씨·OAuth·위치 API는 일반 E2E에서 항상 목업이다.
