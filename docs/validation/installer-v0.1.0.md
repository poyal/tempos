# v0.1.0 Windows 설치 EXE 검증

2026-10-13, Windows 11 Pro 10.0.26300 x64의 실제 사용자 세션에서 검사한다. Passport의 현재 사용자용 NSIS 설치 EXE 구성을 참조했다. Tempos는 네이티브 앱이므로 Electron을 추가하지 않으며 MSI가 아닌 설치 EXE를 제공한다.

## 배포와 동작

입력은 공개된 `Tempos-0.1.0-win-x64.zip`이다. 앱 실행 파일은 재빌드하지 않고 사용자 문서와 설치 도구 고지만 갱신한다. 기존 ZIP과 `v0.1.0` 소스 태그는 유지하며 설치 패키징 소스는 `v0.1.0-win-x64-installer` 태그로 보존한다.

| 항목 | SHA-256 |
| --- | --- |
| 기존 공개 ZIP | `AE9EF44AEDD4367237F4A5CF92A04ED748445F6635E9583074F1371817CA60A3` |
| 앱 Tempos.exe | `E8DEDCF6299A7BD47FA89F470D03CBF34B97DC1F94C9633B27E788315D84ED61` |

NSIS v3.04 Unicode, 현재 사용자 설치, `asInvoker` 실행 수준, 기본 경로 `%LocalAppData%\Programs\Tempos`를 사용한다. 첫 화면에서 폴더를 고르며 전체 사용자 설치와 권한 상승 도우미는 제공하지 않는다. 한글·공백 경로, 바탕화면·시작 메뉴, Windows 설치된 앱 등록과 제거를 지원한다. 실행 중인 앱을 덮어쓰거나 강제 종료하지 않는다.

## 검사 범위

`--installer`는 API를 사용하지 않는 시계 전용 별도 프로파일로 설치 앱을 실행한다. 모든 파일 해시·바로가기 대상·지역표 로딩·설정 저장·재시작·같은 폴더 재설치·제거·설정 보존을 검사한다. 전체 사용자 옵션·루트 경로·다른 폴더 제거·실행 중 설치와 제거 거부를 확인하고, 해당 설치본의 시작 등록만 제거하는지 비교한다. 사용자 앱과 설정은 변경하지 않는다.

동일 버전 재설치는 검사하지만 아직 존재하지 않는 다음 앱 버전으로의 업그레이드를 검사했다고 표시하지 않는다. 실제 재로그인·외부 API·Windows SmartScreen 평판·새 PC 전체 환경은 이번 설치 검사 범위가 아니다. 앱 자체의 Release/ASan·목업 API E2E 결과는 같은 실행 파일의 [기존 릴리즈 검증](release-v0.1.0.md)을 참조하며 다시 실행한 수치로 합산하지 않는다.

최종 설치 EXE의 해시·명령·검사 개수와 공개 다운로드 대조는 검증 후 이 문서에 후속 기록한다. 설치 파일 내부 문서는 포장 직전의 기록이며 후속 영수증은 저장소에서 확인한다.

## 수정과 재검사

- 첫 루트 경로 검사에서 NSIS가 잘못된 `/D=`를 기본 설치 폴더로 바꾸는 동작을 발견했다. 테스트가 만든 기본 설치를 자체 제거 프로그램으로 정리하고, 원래 명령줄 경로를 직접 검증하도록 수정했다. 이어진 실행의 기존 설치 사전 검사 실패도 보존했다.
- NSIS `GetFullPathName`이 생성 전 폴더에서 빈 문자열을 반환해 한글 경로 설치가 중단됐다. Windows 경로 정규화 API로 바꾼 뒤 실제 설치를 확인했다.
- 시험 앱의 첫 창이 숨김 상태여서 UI 자동화가 창을 찾지 못했다. 테스트 소유 PID의 네이티브 창으로 연결하고 표시하도록 수정했으며 종료·실패 정리도 소유 PID를 기준으로 한다. 실제 앱 소스나 사용자 설정은 바꾸지 않았다.
- `e2e-20261013-221342-266`에서 설치·실행·재설치·제거를 모두 통과했다. 이후 설치 그림과 문서를 갱신했으므로 이 실행은 개발 중 확인으로만 보존하고 최종 배포 결과와 합산하지 않는다.

개발 중 실행 로그와 결과는 `artifacts/installer-lifecycle-*.log`, `test-results/e2e-20261013-*`에 유지한다. 실패를 최종 성공 실행으로 덮어쓰지 않는다. [README 설치 화면](../../README.md#install)은 실제 설치 창을 촬영한 것이다.
