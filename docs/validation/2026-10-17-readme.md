## API·사용자 데이터 경계

외부 날씨·Google Calendar·OAuth는 HTTP 응답 목업으로 실제 파서·캐시·저장 경로를 통과했다. Google 승인은 앱 소유 루프백 콜백으로 모의했다. 현재 위치는 예제 좌표를 주입했으며 Windows 측위 권한을 요청하지 않았다. 총 15개 목업 요청에서 미등록 요청·실제 서버 대체 요청은 0개다.

CPU·GPU·메모리·디스크·네트워크 수치는 예제 공급자를 사용했다. CPU 온도는 직렬화된 센서 응답과 설치 결과를 목업했다. 실제 CPU 서비스/PawnIO 설치·제거·UAC는 실행하지 않았다. 창·파일·DPAPI·저장 후 재시작은 실제 Windows 경로를 사용했다.

TestHost와 실행별 데이터 폴더, 테스트 전용 시작 등록을 사용했다. 각 최종 실행에서 설치된 앱의 원본 레이아웃·백업·시작 등록이 변경되지 않았음을 확인했다.

## 최초 실패와 재촬영

1. 샌드박스의 핵심 검사는 118개 통과 후 DPAPI 저장에서 실패했다. 실제 Windows 사용자 컨텍스트에서 다시 실행해 243개를 통과했다.
2. 최초 `--ui-review` 두 번은 재시작 후 가려진 크기 선택 상자·적용 버튼을 UIA 검색으로 찾지 못했다. 네이티브 조작용 헬퍼가 해당 테스트 창의 실제 Win32 자식 컨트롤을 직접 찾도록 보완했다. 접근성 검사는 별도로 유지했다.
3. 첫 `--readme` 실행은 기능 검사 53개를 통과했지만 육안 검수에서 네트워크·날씨 선택값의 다시 그리기가 덜 끝난 화면을 발견했다. 촬영 전에 실제 창과 자식 컨트롤의 다시 그리기를 완료하도록 수정한 뒤 18장을 다시 촬영하고 53개를 재검사했다.

실패·대체 실행은 결과 JSON의 `earlierAttempts`와 `initialSandboxAttempt`에 보존했다.
