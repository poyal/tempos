# v0.1.0 Windows 릴리즈 검증

2026-10-13, Windows 11 Pro 10.0.26300 x64의 실제 사용자 세션에서 실행했다. 앱 소스 기준은 `364329e`이며 이 릴리즈 작업은 README·촬영 도구·문서·패키징을 변경했다. 앱 소스는 변경하지 않았고 Release/ASan을 각각 새로 빌드했다. 최종 태그는 `v0.1.0`이다.

## 실행 결과

| 검사 | 통과 | 실패 | SKIP |
| --- | ---: | ---: | ---: |
| Release 핵심 검사 | 202 | 0 | 0 |
| ASan 핵심 검사 | 202 | 0 | 0 |
| 위젯·크기·상태 `--ui-review` | 471 | 0 | 0 |
| README 사용법 `--readme` | 48 | 0 | 0 |
| API 경계 `--api-mock` | 58 | 0 | 0 |
| 날씨·캐시 `--weather` | 63 | 0 | 0 |
| 실제 Windows 수집 `--windows-real` | 40 | 0 | 1 |
| 자동 시작 `--startup` | 20 | 0 | 1 |
| 크기·단위·설정 `--options` | 83 | 0 | 0 |
| **E2E 합계** | **783** | **0** | **2** |

Release/ASan 핵심 검사는 E2E 합계에 포함하지 않는다. 기존 컴파일 경고는 남아 있으나 빌드·검사 종료 코드는 모두 0이다. 테스트 실행별 시각·명령·단언·바이너리 해시는 [기계 판독 기록](release-v0.1.0.json)에 있다.

두 SKIP은 자동화 세션의 OS 마우스 커서 이동 미관측과 실제 Windows 로그아웃/재로그인이다. 자동 시작은 격리된 레지스트리의 등록 명령 실행·재시작·해제·실패 복구까지 검사했다. 실제 외부 날씨 API·Google 웹 승인·실제 위치 권한은 실행하지 않았다.

API는 모두 목업이다. 실제 HTTP 응답 파서·캐시·OAuth 콜백·DPAPI·설정·창·재시작을 거치며, 미등록 요청 또는 실제 서버로의 대체 요청이 없음을 확인했다. `--windows-real`과 `--api-mock`의 로컬 시스템 수집은 실제 Windows 카운터를 사용한다. 별도의 사용자 프로파일·개인 키·실제 좌표를 사용하지 않았다.

## 이미지와 문서

위젯 9종 37개 크기, 소개 보드 9장, M 크기 모음, 사용법 17장, 날씨 추가 상태 3장을 검토했다. 실제 위젯 영역의 크기 비율을 유지했으며 글자·아이콘·날씨 배경을 이미지 편집으로 바꾸지 않았다. 모든 소개 보드·캘린더 XL·설정 캡처에서 글자 위치, 잘림, 이미지 가림, 개인 정보 노출을 확인했다.

첫 `--readme` 실행도 통과했지만 150% 배율에서 설정창 하단 상태 문구가 잘려 보여 실제 창을 60px 늘리고 다시 촬영했다. 이전 성공 실행을 보존하되 합계에서는 제외한다. 위젯 캡처와 앱 바이너리는 동일하다. [촬영 원본·해시](../assets/v0.1.0/captures.json), [현재 화면 안내](../screenshots.md#release-010).

갤러리는 Chrome에서 모든 이미지를 디코딩하고 1200px/390px 화면에서 가로 넘침이 없음을 확인했다. 문서·이미지·명시적 앵커·67개 PNG 해시는 `node scripts/verify-docs.cjs`로 검사한다.

## 배포 절차와 범위

`./scripts/package.ps1 -SkipBuild -Version 0.1.0`으로 위에서 검증한 Release 실행 파일을 재빌드 없이 ZIP에 넣는다. ZIP을 새 폴더에 풀어 실행 파일 해시·x64 PE 형식·버전·지역 자료·사용자 문서와 이미지·외부 고지를 확인한다. TestHost·개인 설정·인증 파일은 배포하지 않는다.

README와 사용법 이미지는 ZIP에 포함한다. 과거 디자인과 개발 지침 링크는 해당 태그의 저장소로 연결한다. 로컬 문서 링크와 이미지 해시 검사는 압축을 푼 폴더에서도 수행한다. 배포판으로 실제 API를 요청하는 검사는 이번 작업에 포함하지 않는다.

게시 대상은 `Tempos-0.1.0-win-x64.zip`과 `.zip.sha256` 두 파일이다. GitHub가 기본 제공하는 소스 아카이브는 별도 실행 파일이 아니다. 게시 후 같은 ZIP을 재다운로드하여 SHA-256이 일치하는지 확인하고, 그 결과는 이 문서의 후속 기록으로 남긴다. ZIP 자체의 해시는 ZIP 내부에 넣지 않고 외부 체크섬 파일에 기록한다.

## 게시 후 확인

[v0.1.0 Windows 릴리즈](https://github.com/poyal/tempos/releases/tag/v0.1.0)를 소스 커밋 `7e05b58`의 태그로 게시했다. 첨부 파일은 Windows x64 ZIP과 SHA-256 파일 두 개이며 ZIP 크기는 6,838,257바이트다.

게시된 두 파일을 새 폴더로 재다운로드했다. 내려받은 ZIP·공개 체크섬·로컬 검증본의 SHA-256이 모두 다음 값과 일치한다.

```text
AE9EF44AEDD4367237F4A5CF92A04ED748445F6635E9583074F1371817CA60A3
```

새로 압축을 푼 패키지는 파일 135개, 국내 지역 3,837개, 실행 파일 `Tempos.exe` 하나를 포함한다. x64 PE·버전 0.1.0·Release EXE 해시 일치, TestHost·개인 설정·인증 파일 부재, 패키지 안의 문서 참조 280개와 PNG 67개 해시를 확인했다. 공개 태그의 README에도 크기별 갤러리가 포함되어 있다.

[게시 시각·첨부 파일·다운로드 검증 기록](release-v0.1.0-published.json). 이 절과 게시 영수증은 릴리즈 후 문서만 추가한 기록이다. 게시한 ZIP·소스 태그·실행 파일은 변경하지 않았다. ZIP 내부 문서는 게시 직전 검증 기록이며 이 후속 절은 저장소에서 확인한다.

같은 날 이후 현재 사용자용 설치 EXE와 체크섬을 추가했다. 위 ZIP·앱 실행 파일·기존 태그를 유지했으며 [설치형의 별도 검사와 공개 다운로드 확인](installer-v0.1.0.md)을 참조한다.
